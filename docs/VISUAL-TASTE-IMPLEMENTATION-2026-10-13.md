# Visual taste implementation — 13 October 2026

Mellox now has an additional visual evidence and approval layer inside the existing Brand → Look & voice editor. Existing app navigation, surface styles, colours, controls and layout conventions are preserved. The new controls use the current design system; no landing-page redesign is included. The original generation flow remains the default.

## Compatibility with existing generation

- Without an approved visual profile, Studio keeps the original image prompts, model fallback, reference packet, one bounded repair, review-before-logo order and requested approval behaviour. Existing writing/chat callers resolve the original Look without querying visual evidence.
- With an approved profile, relevant visual rules and references supplement the current generator. Caption generation and its rewrite continue using the existing writing style. Explicit manual Look settings take priority over inferred settings. Visual evidence has a separate section so it does not replace or truncate the existing brand context.
- Editable text/layout composition and theme locks are off by default. Analysis cannot silently enable either, even if its model response requests them. The user enables those switches explicitly in the existing editor.
- New video sessions still generate a video directly and use the original video meter. A still-frame preview is optional. Legacy UGC requests retain their existing provider limits/fallback behaviour; required-reference checks apply to requests using the additional layer. UGC freezes the absence of a profile as well as an approved profile, so a later approval cannot change an existing retry. Retries started before this feature keep their original request.
- Missing optional evidence falls back to the existing flow. Unavailable optional reference images retain saved guidance and surface a Studio warning. A reference-store outage cannot discard a paid image. Ordinary advisory warnings do not introduce a new automatic-approval rule. Only unfinished video previews have the new publication restriction.

## Implemented flow

1. Capture a public homepage, up to three discovered representative pages by default, and a mobile homepage. The user can request up to eight pages. Retain full-page screenshots and readable section crops as private workspace assets. Use light gallery previews and lazy loading while retaining complete originals for inspection and model evidence. Long pages are capped at 18,000 pixels and marked partial. Lazy imagery, measured typography and page coverage are included.
2. Analyse a balanced selection of evidence across pages and user references. Propose two or three directions with sourced observations and confidence. Website/customer examples are distinguished in the analysis instructions; a user still confirms the proposed identity.
3. Add uploaded images/short videos, direct public image links or existing library images. Describe what to follow or avoid, identify product/person references, and optionally scope a reference to a campaign or format. Edit descriptions, remove references, undo or restore later. Video removal also removes its derived reference frames from selection.
4. Compare inexpensive layout previews, choose a direction, adjust its description, layout/background, consistency lock and editable composition. Approval is explicit and atomic. Rescans create candidates; they do not replace the active profile. Approved versions can be restored, or the user can return to their manual look. The active profile is linked from Brand DNA and maintained in its own authoritative settings row; older browser saves cannot erase that link. An older active profile and its references remain accessible after many scans.
5. Freeze the selected direction, resolved manual settings and source identities on Studio jobs. Image generation receives relevant references through its existing renderer. If editable composition is enabled, keep original art separately and render exact text with brand layouts. Those images support text edits without generating the artwork again, preserve the real logo, and return affected posts to review together.
6. Carousels and Stories receive the approved typography, palette and visual guidance. The original theme selection and complete model-generated frames remain available by default. Explicit theme locks fix the selected layout/background/motif; explicit editable composition selects the deterministic layout path. Direction previews illustrate design possibilities using source imagery and do not promise exact generated output.
7. Video generates directly by default. The user can enable a still first-frame preview, charged as an image. Making the video uses the saved frame and video allowance. Preview assets cannot be approved or scheduled as finished videos. Successful video completion clears the preview restriction against the actual linked video asset. Further video revisions can reuse the saved first frame.
8. Studio and UGC requests with the additional reference layer use providers that preserve required references, while legacy provider requests/fallbacks remain unchanged. Optional reference limits are recorded against the actual provider request. UGC retries keep their frozen direction. Video references are sampled offline; still imagery does not invent pacing or music preferences. Motion preferences remain editable in the existing Video controls.
9. Extend image review with selected evidence for approved-profile renders, after any explicit composition and logo placement. Keep the original review-before-logo path without a profile. Permit one bounded art repair; editable typography/logo defects are surfaced rather than asking a scene generator to redraw text layers. Review representative video frames and retain them privately. Unavailable checks and font substitutions are advisory warnings; the existing approval logic is preserved.
10. Record targeted feedback against the exact generated profile and sources. Repeated explicit feedback adjusts bounded reference ranking and adds guidance for theme, identity, clutter, typography or generation artifacts on new renders. A single rejection does not rewrite permanent brand locks, and corrections preserve the approved medium/layout and the current brief. Avoid descriptions become scoped generation constraints; avoid images are not copied into the subject-reference packet.

## Storage and access

Migration: `supabase/migrations/20261015090000_brand_visual_taste.sql`.

It adds capture jobs, evidence sources, immutable profile versions, active settings and feedback. Membership limits reads; browser roles cannot write these tables directly. Service writes validate linked workspace ownership. A unique constraint prevents concurrent scans for one workspace. Worker leases, cancellation checks and atomic completion prevent cancelled analysis from replacing the brand's direction. Text replacement uses a transaction and refuses scheduled/published posts or stale output versions.

Capture navigation, redirects and subresources all use the existing DNS/redirect-guarded fetcher. No personal browser profile, cookies, authenticated pages, forms, WebSockets or unrestricted browser networking is used. Uploads are bounded before multipart parsing, including chunked uploads, and checked for format, bytes, image pixels or video duration. Source media remains private and workspace-specific.

## Runtime and release

- Apply the migration through the normal reviewed migration workflow, then deploy the application/container changes. This task has not changed the live database or deployed production.
- The container config sets `VISUAL_CAPTURE_BROWSER_PATH=/usr/bin/chromium` and installs Chromium's sandbox helper. [Debian's package reference](https://packages.debian.org/bookworm/chromium-sandbox) describes that helper. The host must support Chromium's OS sandbox; this implementation does not silently disable it.
- Local workers may use `VISUAL_CAPTURE_BROWSER_PATH` or `VISUAL_CAPTURE_BROWSER_CHANNEL=chrome|msedge`. Windows development prefers an installed Chrome or Edge. Use a browser supporting the uploaded MP4/WebM codec.
- Existing authenticated polling and the schedule-worker route advance one capture checkpoint at a time. Polling is not required to keep a scan alive; cron resumes due jobs. Secondary-page failures are retried, then skipped with coverage warnings. Homepage failure is explicit.
- First visual analysis is included. Further analyses use the existing `brand_dna_rescan` meter (125 credits), shown in the editor before the user starts one. Provider calls use existing budgets and metering. Paid live quality tests were not silently run.
- The optional `MELLOX_BUILD_WITHOUT_CACHE=true` setting disables temporary webpack cache writes on small disks. Default development/deployment behaviour is unchanged.

## Practical limits and pilot acceptance

This is reference learning and retrieval, not a fine-tuned private image model. Website analysis can still misclassify a customer's work or embedded example; evidence review and approval remain necessary. The system analyses up to eight selected image crops per pass, rather than pretending every pixel participates in each generation.

Editable typography uses Mellox's font catalogue. Unavailable/unsupported fonts are surfaced; exact custom font-file ingestion is not included. Offline browser decoding supports its available codecs and references up to 30 seconds/12 megapixels. Three sampled frames support appearance checks, not a complete temporal/audio assessment.

The current video pipeline provides an approved first frame and reference-aware render. It does not provide a separate shot timeline, per-shot regeneration, music-rights library, automatic speech-aligned captions or a deterministic video logo/caption compositor. Audio, transitions, caption timing and identity between sampled frames require human review. These provider/pipeline extensions from the longer-term plan remain future work.

Actual quality improvement requires a permissioned pilot; it is not established by fixture tests. Use 5–10 real brands spanning photography, illustration, editorial and product-heavy identities. Compare the previous and new pipelines on the same briefs, with a stated provider budget and blind user preferences. Record sample size, first-pass acceptance, theme corrections, product/copy defects, time to approval and total cost per accepted piece. Keep visual preference separate from campaign effectiveness. The proposed 70% first-pass acceptance target remains a target, not a measured result.
