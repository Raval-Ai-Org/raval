# Canva integration

Settings → Connections stores one Canva grant per Mellox workspace. OAuth uses a ten-minute, single-use server state, PKCE, authenticated user and workspace binding, and a safe internal return path. The callback is `/api/integrations/canva/callback`. Configure `CANVA_CLIENT_ID`, `CANVA_CLIENT_SECRET`, and base64 32-byte `CANVA_TOKEN_ENCRYPTION_KEY` server-side. Register `https://mellox.ai/api/integrations/canva/callback` and `http://localhost:8080/api/integrations/canva/callback` in Canva. `FEATURE_FLAG_CANVA_MAGIC_LAYERS_ENABLED=false` is the safe default.

For a deployed instance, set `APP_URL` to its public HTTPS origin and register that exact origin plus `/api/integrations/canva/callback` in Canva. Keep `CANVA_TOKEN_ENCRYPTION_KEY` stable across deployments: existing grants are encrypted with it. If the key has changed, Settings → Connections now reports the unreadable grant as needing attention; reconnect Canva to save a grant with the current key. Deploy the Canva Supabase migrations separately from the web build, and check the connection status in Settings before using “Edit with Canva.”

Scopes: `asset:read asset:write design:content:read design:content:write design:meta:read profile:read`. The last scope is required by [Canva's capability endpoint](https://www.canva.dev/docs/apps/rest-apis/reference/users/get-user-capabilities/) and existing grants must reconnect to use capability detection.

`canva_oauth_credentials` is service-role only and stores AES-256-GCM encrypted access and refresh tokens. The server gateway refreshes tokens and normalizes errors. The browser receives only connection status, mapping identifiers, mode, and a validated Canva editor URL. Disconnect deletes usable local credentials and attempts revocation. Audit records connection, disconnection, design creation, import and selection without credentials.

## Editing

“Edit with Canva” resolves workspace-owned stored assets server-side and uploads bytes into Canva. When the Magic Layers flag is on and the account advertises `image_to_design_imports`, the server starts and polls the [Preview Image-to-Design job](https://www.canva.dev/docs/apps/rest-apis/reference/design-imports/create-image-to-design-import-job/). A successful result is recorded as `magic_layers`. Canva reconstructs elements where possible; fidelity depends on the source. Capability, preview, quota, rate limit and conversion errors use the [standard Create Design API](https://www.canva.dev/docs/apps/rest-apis/reference/designs/create-design/) as `flat_image`. Its text inside the uploaded image is not individually editable. The flag is off in public production because Canva says public integrations using Preview APIs cannot pass public review. The normal flow works independently.

Mellox carousels retain ordered `meta.slides` text, roles and a theme in addition to rendered JPEGs. A native PPTX with editable text boxes and shapes is built from this structure, one PowerPoint slide per carousel page. The [Canva Design Import API](https://www.canva.dev/docs/apps/rest-apis/reference/design-imports/create-design-import-job/) imports it into one multi-page Canva design (`design_import`). The PPTX expresses the structured content and palette; it is not a pixel-perfect copy of the rendered slides. If PPTX import is unavailable, the standard Create Design flow makes one flat design per slide and exposes links in slide order. Canva's REST Create Design endpoint does not provide an operation to add pages from arbitrary uploaded assets. Mellox does not concatenate slides.

## Importing changes

The user returns to Mellox and clicks “Import Canva changes.” The server starts an asynchronous [PNG export](https://www.canva.dev/docs/apps/rest-apis/reference/exports/create-design-export-job/), polls with a bound, validates page count, downloads every temporary URL immediately through the guarded fetcher, validates PNG MIME and dimensions, and saves each page through the canonical asset persistence and metadata finalization path. `canva_import_versions` and `canva_import_pages` retain sequential versions, ordered page assets and provenance. New assets reference the original source asset as parent. Original assets are not overwritten. “Use Canva version N” explicitly selects an imported version for a content item; scheduled and published items are rejected, and an approved item returns to draft for review. No continuous Canva polling occurs. Asset-only imports create a new Library asset version without changing any content item.

All server actions require an explicit workspace and editor role. Source assets, mapping, version and pages are checked within the workspace. Raw tokens and temporary export URLs are never returned to the browser or persisted as asset identity. Provider download URLs must be HTTPS Canva hosts, then pass Mellox's SSRF-safe fetch and size checks. Async jobs have bounded polling and normalized errors.
