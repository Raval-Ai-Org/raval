# Mellox AI Canva security audit

Audit date: 2026-10-12. Evidence: current checkout, local configuration presence checks, application tests, actual SQL functions executed in PGlite/PostgreSQL, and official Canva documentation. This is **not** an attestation of the deployed application, Developer Portal configuration, hosting accounts, or legal compliance. No deployment or live Canva write was performed.

## Verified implementation and changes

| Area                 | Evidence and result                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Purpose              | An authenticated workspace editor selects Mellox images or carousels, opens a Canva design, and explicitly imports the edited PNG pages as new Mellox assets. The integration does not enumerate all of a person's Canva designs.                                                                                                                                                                                                                                                                                                                                                                                                                   |
| OAuth                | Server-side authorization-code flow with S256 PKCE; state and verifier use 48 random bytes each. State is stored as SHA-256, bound to the authenticated user and workspace, valid for ten minutes, and atomically consumed once. The verifier is encrypted and cleared on consumption. Added database-error handling, verifier format validation, and an expiration condition on the consumption write.                                                                                                                                                                                                                                             |
| Redirects            | Authorization and token exchange use a fixed callback derived from server APP_URL, never a client-supplied callback. Return paths must be internal relative paths. Added rejection of credentials, query, fragment, non-root paths and production loopback origins. Callback fails closed when configuration is invalid. HTTPS non-loopback origins remain configurable; actual Portal registration must be verified separately.                                                                                                                                                                                                                    |
| Scopes               | All five scopes are used: asset:write uploads image bytes; asset:read polls upload jobs; design:content:write creates/imports designs; design:meta:read obtains an existing design's editor URL; design:content:read exports PNG pages. No profile, brand-template, folder, collaboration or webhook scopes are requested.                                                                                                                                                                                                                                                                                                                          |
| Tokens               | AES-256-GCM with fresh 12-byte IVs and authentication tags. HKDF-SHA256 derives a provider-specific 32-byte key from SUPABASE_SERVICE_ROLE_KEY when present; a valid dedicated CANVA_TOKEN_ENCRYPTION_KEY is also accepted as a legacy read key or fallback without that root credential. Tokens live in separate encrypted columns **in the same service-role-only credential record**, not physically separate storage systems. No KMS/HSM, independently managed encryption key, automatic rotation, or certification is established.                                                                                                            |
| Authorization        | Supabase authentication plus explicit workspace roles; mutations require editor or higher. Read-only connection status permits viewers. Credential table denies anon/authenticated access; mapping tables have workspace RLS. The server's service-role client bypasses RLS, so server role checks remain essential.                                                                                                                                                                                                                                                                                                                                |
| Credential races     | New migration provides service-only installation, withdrawal and refresh functions that lock the workspace row. Installation rechecks membership and consumed, unexpired, non-withdrawn state; connection and encrypted credentials are saved together, then finalized state is deleted. Withdrawal atomically deletes pending states and credentials and marks connection metadata revoked. Refresh conditionally writes only active, matching credentials. Failed installation attempts provider revocation. Newly installed grants store validated Canva user/team IDs from /users/me in connection metadata, without additional profile scopes. |
| Refresh              | Expiring access tokens refresh with a 60-second skew; an in-process promise avoids duplicate refreshes. New transactional compare-and-set prevents overwriting newer credentials. The service rechecks active status before returning a refreshed token or a concurrent instance's saved token. A late refresh after withdrawal attempts to revoke the newly returned grant.                                                                                                                                                                                                                                                                        |
| Disconnect           | Requires an authenticated editor. Removes local authorization atomically, then calls Canva's revocation endpoint. Non-2xx/network/configuration/decryption failures are not represented as confirmed remote revocation. UI tells users to remove Mellox in Canva account settings when confirmation is unavailable. No automatic remote retry job is implemented after local credential deletion. Imported assets/design mappings deliberately remain.                                                                                                                                                                                              |
| Workspace deletion   | Existing owner-only, typed-confirmation flow now invokes Canva withdrawal/revocation before deleting workspace database rows. Canva credentials and mapping/version tables use workspace deletion cascades. Object-storage cleanup remains best effort; successful database deletion must not be described as guaranteed erasure of every object or backup.                                                                                                                                                                                                                                                                                         |
| Provider URLs        | Canva API calls use a fixed HTTPS base, a 20-second timeout, no cache and now reject redirects. Editor URLs must have the exact HTTPS www.canva.com origin and no embedded credentials. Exports require HTTPS Canva hosts and default HTTPS port; the guarded downloader now checks that provider boundary on every redirect as well as its existing private-IP/DNS protection and byte/time limits.                                                                                                                                                                                                                                                |
| Rate limits and logs | Server functions already have connector rate limits. Added the same start limit to the direct GET connect route. The shared rate limiter fails open if its database limiter fails; it is not a guaranteed outage-time limit. Removed attacker-controlled error descriptions from callback logs. Authentication code/state still travel in the OAuth callback query; production proxy/hosting access-log redaction needs verification.                                                                                                                                                                                                               |
| Webhooks             | No Canva webhook receiver, signature verifier or event subscription exists in the repository. Other providers' webhook controls do not establish Canva verification. Answer "not used" rather than claiming verification. Confirm Portal subscriptions are absent; implementing webhooks later requires Canva's documented signature verification and replay handling.                                                                                                                                                                                                                                                                              |
| Preview API          | Image-to-Design is a Canva preview endpoint. Changed the production default to disabled and the environment example to false. Explicit true still enables it for private/local testing; set false in production for public review. Stable image placement and editable PPTX import remain available.                                                                                                                                                                                                                                                                                                                                                |
| SCA                  | Existing CI defines npm audit --omit=dev --audit-level=high on PRs/pushes. Actual production dependency audit: six moderate findings, zero high or critical. Affected packages: @mastra/core, gray-matter, js-yaml, mammoth, argparse, sprintf-js. Suggested fixes include major/downgrade changes; no blind npm audit fix applied. The gate does not fail for moderate findings or cover Python/development dependency vulnerabilities.                                                                                                                                                                                                            |
| SAST                 | Existing lint/type checks and custom secret scanning are not dedicated SAST. Added a Semgrep 1.180.0 workflow using p/security-audit, failing on findings, with metrics disabled and read-only repository permissions, on PRs/pushes and weekly. YAML parsed successfully. **Scanner execution and findings triage remain pending**; do not answer that scheduled scans already operate. Rule pack is fetched from the registry and is not version-locked by this workflow.                                                                                                                                                                         |
| Secret scanning      | Executed repository scanner successfully on 3,082 tracked files. This is a custom pattern scan of the working tree, not proof that historical commits, ignored environment files or hosting secrets are clear.                                                                                                                                                                                                                                                                                                                                                                                                                                      |

Disconnect does not delete these files. Workspace deletion attempts recursive cleanup in both storage providers; failures have no guaranteed retry or certified erasure process.                                                                                                                         |
| Temporary export URLs and image bytes                                        | URLs and buffers in server process memory during bounded export/download/image normalization; no persisted export URL identity or browser token exposure in this adapter.                                                                                                                                                            | No application-level persistence of temporary export links. Server/proxy/provider logging behavior is not verified.                                                                                                                                                                                                                       |
| Audit identifiers and operation history                                      | Supabase audit_logs through recordAudit; workspace/user/action/entity identifiers.                                                                                                                                                                                                                                                   | No Canva-specific fixed retention or backup-erasure schedule established.                                                                                                                                                                                                                                                                 |

Canva receives user-selected images, design titles/content and authorization requests. Supabase receives encrypted credentials and metadata; imported assets may be in R2 or, for older files, Supabase Storage. The hosting server processes them transiently. Users can subsequently use imported workspace assets in Mellox features, including publishing and other selected integrations; inspect that selected downstream workflow before asserting that images never leave the configured storage provider. The ordinary Canva adapter does not send exported images or OAuth tokens to a third-party AI provider. The optional preview conversion runs at Canva. This audit does not establish a product-wide promise that user-selected imported content can never be used in AI workflows.

No storage country, Supabase project region, hosting region, replica location, subprocessor contractual terms, backup location, or backup retention has been verified. A supabase.co hostname is not evidence of a storage country. No fixed retention period, SOC 2/ISO certification, penetration-test history, guaranteed deletion deadline, MFA enforcement or staff-access review can be inferred from this repository.

## Remaining controls and operator confirmations

1. Verify the actual deployed revision, Supabase migrations/RPC grants/RLS/private bucket, production APP_URL, secrets, HTTPS termination and Canva Portal settings. Local .env has the public HTTPS APP_URL, while .env.local uses localhost; production must not inherit the localhost override. Presence checks did not print secret values or establish that configured credentials are valid.
2. Apply 20261012090000_canva_atomic_authorization.sql **before** the matching server deployment. Existing integrations will not function with the changed server if the new RPCs are missing. No migration was applied remotely.
3. Set FEATURE_FLAG_CANVA_MAGIC_LAYERS_ENABLED=false for public submission; register exactly https://mellox.ai/api/integrations/canva/callback and enable the five used scopes. Development loopback callback is only for a development integration/environment. Confirm no Canva webhook subscriptions exist externally.
4. Confirm storage countries, regional replicas, hosting provider and all processors receiving Canva data. Provide operational evidence of backup encryption, schedule, retention, restore testing and deletion handling after restoration. No backup jobs or restore-drill evidence were found in this audit.
5. Establish and implement retention rules for abandoned OAuth states, retained design metadata/assets, audit logs, and backups. Policy claims must distinguish authorization expiry from data deletion. Do not invent a days-based retention period.
6. A user-account erasure workflow was not found. Deleting auth.users can clear user-owned state while connected_by/created_by references become NULL; it does not automatically withdraw a workspace grant or erase a shared workspace. Define ownership-transfer and account-erasure handling and verify all workspace owners' deletion requests.
7. Object-storage cleanup is best effort and its existing removed-count records listed paths, not verified removals. A deletion retry/outbox and confirmation process remain missing. Imported assets/designs intentionally remain after integration disconnect; users need a separate content/workspace deletion path.
8. Refresh writes are now serialized and conditional, but outbound refresh calls are only deduplicated within one server instance. Canva uses rotating refresh tokens; distributed instances can still race and require reconnect if the other instance has not saved its rotated grant yet. A distributed lease and provider round-trip tests remain follow-up work. Do not claim distributed exactly-once refresh.
9. Execute the new SAST workflow, triage findings, validate registry access and make appropriate security checks required in branch protection. Verify existing CI runs rather than treating workflow files as execution evidence. Add broader SCA coverage if claiming scans for all runtime/development/Python dependencies; triage the six moderate production dependency findings.
10. Confirm incident contact, vulnerability remediation deadlines, staff access/MFA, environment secret management and key-rotation procedures. Rotation of the Supabase root credential affects derived-token decryption; retain a compatible read key or plan controlled reconnects. No automatic key migration/KMS is claimed.
11. External revocation in Canva is not pushed to Mellox. The connection-status endpoint checks local configuration and credential decryptability, not remote grant validity. Provider authorization failures prompt reconnect on an attempted operation; they do not automatically erase all locally retained credentials/content. Confirm this behavior against any withdrawal/deletion claims.

12. Canva recommends storing access and refresh tokens separately. They are currently separately encrypted columns in one credential record; distinct storage systems/tables and narrower per-token service privileges are not implemented. Do not describe this as physical separation. The audit explicitly leaves this as a recommended storage-hardening gap, requiring a staged change that preserves existing grants.

## Validation

- Focused Vitest runs: 104 tests in ten files passed, including thirteen real database security tests, encrypted state consumption/replay rejection, denied workspace permission, failed-installation revocation, withdrawal failures, late refresh after disconnect, callback redirect/logging controls, workspace isolation, workspace-deletion ordering and real cascading deletion of Canva import versions/assets.
- New migration executed in the repository PGlite/PostgreSQL harness and re-applied successfully; service-role-only function grants tested. This proves SQL behavior in the harness, not production configuration or multi-connection load performance.
- Changed-code ESLint, TypeScript, diff and formatting checks passed. Full migration baseline verification replayed 131 migrations and re-applied 105 post-baseline migrations; all 163 public tables had RLS enabled in the harness.
- Secret scan passed; production npm audit found six moderate and zero high/critical findings. No production build, live write, deployment or approval claim.
