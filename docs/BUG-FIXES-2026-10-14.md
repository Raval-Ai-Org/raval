# Additional Mellox bug fixes — 14 October 2026

These changes are local. No production deployment, database migration, public
post, real authentication operation, or paid generation was performed.

| Reproducible failure                                                                                                                                   | Corrected behavior                                                                                                                                    | Regression coverage                                  |

## Implementation

The main changes are in `src/lib/calendar/autosave.ts`,
`src/components/app/ContentCalendar.tsx`,
`src/app/auth/confirm/EmailConfirmPage.tsx`, `src/lib/auth.ts`,
`src/lib/authed-fetch.ts`, `src/lib/workspace/paths.ts`,
`src/lib/stories/schedule.ts`, and `src/lib/schedules.server.ts`.

Browser verification uses the real Next.js client components with synthetic
authentication responses and the development-only calendar fixture. Google
Fonts are replaced only in the verification process with offline declarations;
production source fonts are unchanged. Unit tests exercise failures, concurrent
saves and malformed inputs without real provider calls.

## Content and publishing follow-up

- AI rewrites, editorial saves, imported updates, connector reviews and calendar
  planning now compare the stored revision when writing. A change made during
  that operation produces a `409` conflict instead of overwriting newer text,
  metadata or approval state.
- Editorial status setters no longer manufacture scheduled, publishing,
  published or failed delivery states. The unused legacy rescheduling shortcut
  refuses the request and directs callers to the publishing scheduler.
- Scheduled and publishing posts cannot be edited or rewritten through these
  editorial functions. Posted work returns to draft before editing. Blocked
  rewrites do not start metered generation.
- Deleting a scheduled or publishing post is blocked until delivery is cancelled
  or finished. A concurrent schedule or edit also stops deletion instead of
  removing the record for an active provider post. The review dialog disables
  deletion for these states.
- Discarding a draft now follows the required draft-to-pending-to-rejected
  transition. If the second save fails, the dialog retains pending status so
  the decision can be retried.
- Changing an approved post's format now invalidates approval in the database.
  This requires applying `20261018090000_content_kind_approval.sql`. Calendar-only
  changes and existing lifecycle transitions remain intact.
- Failed optional website reads are reported as an incomplete Publish list with
  a retry action. Older requests and responses from another workspace cannot
  replace the current list.
